# LCK 방송 UI v2 — 캔바 에셋 스펙 (밴픽 바 / 상단 스코어바 / 킬 스냅샷 카드)

이번 라운드는 데이터 레이어만 구현·검증했고(`_extract_bans`, `_reconstruct_kill_snapshot`,
`cogs/highlight.py`), 화면 렌더링(overlay)은 아직 안 붙였다. 이 문서는 다음 라운드에서
캔바로 배경/프레임 PNG를 만들 때 바로 쓸 수 있는 치수/레이아웃/색상 스펙이다.

**중요**: 아래 픽셀 값은 전부 이 세션 내내 테스트에 써온 레퍼런스 해상도
**1920x804**(리플레이 클립 실측값) 기준 예시다. 실제 코드는 (지금 배너가 그렇듯) 매 렌더의
실제 해상도에 비례하는 **비율**로 계산하므로, 에셋 자체는 아래 "네이티브 종횡비"만 정확히
지키면 된다 — 절대 픽셀 크기가 다른 해상도에서 그대로 쓰이는 게 아니다.

## 0. 기존 레이아웃 변경 사항 (1단계 대비)

1단계(`GAME_VIEWPORT_SCALE=0.90`, 하단 여백만 확보)에서 **상단 여백도 추가로 확보하도록
축소 비율을 키우는 게** 이번 v2의 전제다. 아직 코드에 반영 안 됨 — 제안값:

| 값 | 1단계(현재, 커밋됨) | v2 제안 |
|---|---|---|
| GAME_VIEWPORT_SCALE | 0.90 | **0.81** |
| 축소된 게임 화면(1920x804 기준) | 1728x724 | 1556x652 |
| 좌우 여백(각) | 96px | **182px** (밴픽 바 배치용) |
| 상단 여백 | 0px (없음) | **70px** (신규 - 스코어바용) |
| 하단 여백 | 80px | 82px (기존 배너 로직 그대로, margin_height 자동 재계산이라 코드 변경 불필요) |

상단/하단 여백 배분은 "위아래 균형"을 고려하되 완전히 동일하진 않게 잡았다 — 실제 LCK도
하단(이벤트 배너/킬로그) 비중이 상단 스코어바보다 크다. 좌우 여백이 96px→182px로 커지는
부수 효과로 밴픽 아이콘을 넣을 공간이 확보된다(아래 2번 참고).

## 1. 상단 스코어바 (신규 여백, 높이 70px @ 1920x804 기준)

**레이아웃**: 킬러 vs 희생자 구도(요청대로 팀 대항전 아님). 좌측=킬러, 우측=희생자, 중앙=게임 시간.

```
┌──────────────────────────────────────────────────────────────┐
│  [챔피언] 닉네임                14:32              닉네임 [챔피언]  │
└──────────────────────────────────────────────────────────────┘
   ← 좌측 절반(킬러) ─┤              │├─ 우측 절반(희생자) →
```

- **캔바 작업 캔버스**: 1920 x 70px (종횡비 약 27.4:1) — 배너(1920x120=16:1)와 같은 방식으로
  가로로 매우 긴 완성 그래픽 하나
- **배경**: `#0A0B0E`(다크) 바탕, 좌우 끝에서 중앙으로 갈수록 `#5865F2` 포인트가 옅게 들어간
  그라디언트 정도 권장(배너와 톤 통일) — 정적 배경/프레임 전체를 캔바에서 완성
- **동적 오버레이(코드가 나중에 텍스트/아이콘만 그 위에 얹음)**:
  - 좌측: 챔피언 아이콘(원형 마스크, 지름 ~48px) + 닉네임 텍스트(Chakra Petch SemiBold, 흰색)
  - 우측: 동일 구성, 좌우 대칭(닉네임은 오른쪽 정렬)
  - 중앙: 게임 시간 텍스트(MM:SS, Chakra Petch Bold, `#5865F2` 강조색) — 이미 파이프라인에
    있는 `mapping`으로 클립 어느 시점이든 계산 가능(킬 시점 기준 고정 표시 권장)
- **캔바에 미리 그려둘 것**: 챔피언 아이콘이 들어갈 자리의 원형 프레임(테두리), 닉네임/시간
  텍스트가 들어갈 자리의 여백(캔바에 텍스트를 직접 쓰지 않음 - 자리만 비워둠)
- **표시 시점**: 배너와 마찬가지로 킬 이벤트 구간에만(`hud["start"]`~`hud["end"]`) 슬라이드
  인/아웃 권장, 또는 클립 전체 상시 노출 중 택1 — 다음 라운드에서 결정

## 2. 밴픽 바 (좌우 여백 재활용, 각 182px 폭 @ 1920x804 기준)

**위치 제안**: 상단/하단이 아니라 **좌우 여백**(1단계에서 이미 만든 pillarbox, v2에서
96px→182px로 확대됨)을 그대로 재활용 — 새 여백을 또 만들 필요가 없다. 왼쪽 기둥 = 100팀
밴, 오른쪽 기둥 = 200팀 밴, 각 세로로 5개씩 스택.

```
┌──────┐                                              ┌──────┐
│ 밴1  │                                              │ 밴1  │
│ 밴2  │        (축소된 게임 화면 - 손 안 댐)              │ 밴2  │
│ 밴3  │                                              │ 밴3  │
│ 밴4  │                                              │ 밴4  │
│(빈칸)│ ← 밴 없음(championId=-1) 슬롯, 실측으로 확인됨      │ 밴5  │
└──────┘                                              └──────┘
 team 100                                              team 200
```

- **캔바 작업 캔버스**: 세로로 긴 프레임 하나(182 x 652px 정도, 게임 화면 높이에 맞춤) — 5칸
  슬롯 틀(각 슬롯 원형 또는 사각 프레임, 지름/한 변 ~70px, 슬롯 간 간격 ~8px)만 미리 그림
- **"밴 없음" 슬롯**: `_extract_bans()`가 이미 -1을 걸러내므로, 밴이 4개면 5번째 슬롯은
  빈 프레임(반투명 X 표시나 빈 원)으로 남는다 — 캔바에서 "빈 슬롯" 상태도 하나 만들어두면
  코드에서 조건 없이 그대로 겹쳐 쓸 수 있음
- **동적 오버레이**: 슬롯당 챔피언 아이콘 하나(챔피언 id는 숫자라 Data Dragon `champion.json`
  역매핑 필요 - 조사에서 확인된 내용)
- **표시 시점**: 클립 전체 상시 노출 권장(밴픽은 킬 이벤트와 무관한 "경기 전 정보"라 계속
  보여도 자연스러움) — 킬 스냅샷 카드(3번)와 물리적으로 같은 좌우 공간을 다른 시간대에
  나눠 쓸지, 동시에 공존할지는 다음 라운드에서 결정 필요(아래 미해결 항목 참고)

## 3. 킬 시점 아이템/레벨 카드 (하단 배너 좌우 여유 공간, ~304px 폭 @ 1920x804 기준)

**위치**: 3단계에서 검증했던 "배너 옆 빈 공간" 패턴을 그대로 확장 — 배너(1312px 폭 예상)가
중앙에 오면서 좌우로 약 304px씩 남는 공간에 킬러(좌)/희생자(우) 카드 배치.

```
┌──────────────┐  ┌────────────────────────────┐  ┌──────────────┐
│ [챔피언] Lv.7 │  │      "OOO님이 OOO님을        │  │ Lv.5 [챔피언] │
│ 🗡️🛡️🛡️🛡️     │  │         처치했습니다!"        │  │     🛡️🛡️🗡️   │
└──────────────┘  └────────────────────────────┘  └──────────────┘
   킬러 카드              배너(기존, 안 건드림)           희생자 카드
```

- **캔바 작업 캔버스**: 304 x 82px 정도(배너와 같은 높이) — 챔피언 아이콘 자리(원형, ~50px)
  + 레벨 배지 자리(작은 원/사각, 챔피언 아이콘 우하단 겹침) + 아이템 아이콘 자리 3~4칸(각
  ~36px, 가로 나열) 틀만 캔바에서 완성. 킬러 카드/희생자 카드 좌우 대칭이라 하나 만들고
  좌우 반전해서 재사용 가능
- **동적 오버레이**: `_reconstruct_kill_snapshot()`이 반환하는 `items`(id 리스트, 순서만
  있고 슬롯 없음 - 앞에서부터 나열하면 됨)와 `level` 숫자
- **정확도 표기 관련 참고**: 이번 라운드 실측으로 이 재구성은 완전히 정확함이 확인됨(아래
  검증 결과 참고) — 프레임 근사치(±59초 오차) 방식이 아니라 이벤트 재생 방식이라 신뢰 가능
- **표시 시점**: 배너와 동일한 슬라이드 타이밍 재사용(3단계 챔피언 아이콘과 같은 패턴)

## 4. 색상/폰트 (기존 배너와 통일)

- 배경 톤: `#0A0B0E`(다크) / 포인트: `#5865F2`
- 폰트: Chakra Petch (Bold=강조, SemiBold=본문) — `assets/highlight_overlay/`에 이미 있음
- 텍스트/숫자 자체는 캔바에 안 그림(코드가 오버레이) — 캔바는 배경/프레임/아이콘 자리만

## 5. 다음 라운드로 남긴 미해결 결정 사항

1. **좌우 여백 시간 분할**: 밴픽 바(상시 노출 제안)와 킬 스냅샷 카드(킬 이벤트 구간만)가
   같은 좌우 공간을 쓸 수 있는데, 동시에 겹치면 안 되므로 "밴픽 바는 킬 이벤트 구간엔
   숨김" 같은 규칙이 필요할 수 있음 - 혹은 공간을 아예 분리(밴픽을 더 안쪽/바깥쪽으로)
2. **상단 스코어바 표시 시점**: 클립 내내 상시 vs 킬 이벤트 구간만 — 둘 다 근거 있음
3. **GAME_VIEWPORT_SCALE=0.81 확정 여부**: 위 제안값은 이번 스펙 작성을 위한 계산 예시고,
   실제 캔바 에셋이 나온 뒤 프레임 캡처로 자연스러움을 재확인하며 조정 가능성 있음
